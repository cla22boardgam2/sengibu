# 생기부 초안 보조 웹앱 — 설계 문서

작성일: 2026-11-17
원본 요청서: `생기부앱_개발요청서.md` (이 문서가 요청서와 다르면 이 문서를 따른다. 바뀐 점은 맨 아래 "요청서와 달라진 점"에 정리)

## 1. 목적과 이유

초등 담임교사가 학기말 생기부(교과 평어, 창체, 행발)와 통지표 종합의견 초안을 빠르게 만드는 개인용 웹앱.

기존 도구(시간결 see-simple.com)는 평가 수준·칩만으로 틀을 조합해 문장을 만들기 때문에, 같은 수준을 받은 학생들의 문장이 낱말만 바뀐 채 거의 같다. 이 앱은 **학생마다 다른 재료(칩·등급·메모)를 AI가 문장으로 바꾸고, 같은 반에서 이미 쓴 표현을 피하게 해서** 학생마다 다른 초안을 받는 것이 목표다.

참고한 도구: 시간결(틀 조합, 겹침), 반짝 AI 생기부(키워드 690개 — 중복이 많아 고르기 어려움), ACE 평어&행발(일괄 설정, 길이 선택, 추가 지시, 바이트 카운터).

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 칩·등급 버튼 위주로 빠르게 입력하고, 필요하면 메모를 덧붙인다.
- 학생 한 명씩 AI 초안을 받고, 같은 반 첫 어절·같은 학생 다른 항목 초안을 피하게 한다.
- 문장별 근거, 경고, 보충 필요 사항을 함께 보여 준다.
- **돈이 들지 않는다.** 기본은 교사가 직접 만든 **무료 AI API 키(Google Gemini 무료 등급)**로 앱 안에서 바로 생성한다. 예비로 복사·붙여넣기 모드(무료 채팅 AI: Claude·ChatGPT·Gemini 아무거나)를 둔다.
- 처음엔 혼자 쓰고, 나중에 주소만 알려 주면 동료도 쓸 수 있다.

**비목표 (이번 범위 아님)**
- 유료 API(Anthropic 등) 호출. 나중에 다른 AI로 바꿀 수 있게 호출 부분만 한 파일로 분리해 둔다.
- 학기(1학기/2학기) 구분. 자료는 한 덩어리로 둔다(교사 결정). 대신 백업 화면에 "자료 내려받고 비우기" 버튼을 둔다.
- 나이스 자동 입력 크롬 확장 프로그램
- 로그인, 서버 DB, 여러 기기 동기화
- 평가계획서 한글(HWP)·PDF 원본 자동 분석

**실패 조건 (동작해도 실패)**
- 학생 실명이 브라우저 밖(클립보드로 복사되는 프롬프트 포함)으로 나간다.
- 같은 칩·등급만 고른 학생들의 초안이 시간결처럼 내용이 같은데 아무 알림이 없다.
- 복사·붙여넣기가 번거로워 반 전체(25명)를 돌리는 데 시간결보다 훨씬 오래 걸린다.
- `sengibu-prompt.js`의 프롬프트 문구가 바뀐다.

## 3. 제약

- 정적 사이트로 GitHub Pages에 배포. 서버 코드 없음.
- 모든 자료는 브라우저 localStorage에만 저장.
- `lib/sengibu-prompt.js`는 요청서 원문 그대로 저장하고 수정하지 않는다. 앱은 여기서 `buildSystemPrompt`, `buildUserText`, `SECTION_NAMES`, `neisBytes`만 가져다 쓴다. `generateDraft`는 `process.env`와 API 호출을 쓰므로 호출하지 않는다(파일에는 그대로 남겨 둔다).
- 클립보드로 나가는 프롬프트에는 가명(S01…)만 들어간다.

## 4. 검토한 방식

| 방식 | 장점 | 단점 | 결정 |
|---|---|---|---|
| Next.js + Vercel, 서버에서 API 호출 (요청서 원안) | 키를 서버에 숨김, 자동 생성 | API 비용 발생, Vercel 사용 | 제외 — 교사가 GitHub 배포와 무료를 원함 |
| GitHub Pages + 브라우저에서 교사 API 키로 직접 호출 | 무료 호스팅, 자동 생성 | API 비용 발생 | 제외 — 현금 결제 원치 않음 |
| GitHub Pages + 중계 서버(Cloudflare Workers) | 키 숨김 | 비용, 관리할 서비스 추가 | 제외 |
| GitHub Pages + 복사·붙여넣기 모드만 | 비용 0원, 서버 없음 | 학생마다 복사·붙여넣기 — 교사가 번거롭다고 판단 | 예비 모드로만 유지 |
| **GitHub Pages + 교사의 무료 Gemini API 키로 브라우저에서 직접 호출** | 비용 0원, 앱 안에서 바로 생성, 반 전체 자동 | 무료 등급 속도 제한, 무료 등급 입력은 구글이 서비스 개선에 쓸 수 있음, 키가 브라우저에 저장됨 | **선택 (기본 모드)** |

교사 선택: 마지막 방식 + 복사·붙여넣기 예비. 이유: 돈을 쓰지 않으면서 참고 사이트처럼 바로 결과가 떠야 함.

## 5-0. 기본 흐름: 무료 API 키로 바로 생성

- 설정에 **Gemini API 키**와 **모델명** 칸. 키는 localStorage에만 저장하고 코드·저장소에는 넣지 않는다. 키 만드는 법(Google AI Studio, 카드 불필요) 안내 링크를 둔다.
- 호출은 브라우저에서 Gemini API로 직접. system 지침 = `buildSystemPrompt(section, opts)`, 본문 = 기재요령 발췌·참고자료 + `buildUserText(...)`. 응답은 5절 4~5번과 같은 방식으로 JSON 파싱·가명 확인.
- 기본 모델명과 호출 형식은 빌더가 구현 시점의 Gemini 공식 문서에서 무료 등급 모델을 확인해 정한다. 모델명은 설정에서 바꿀 수 있다.
- **반 전체 생성**: 학생 한 명씩 순차 호출. 속도 제한(429)에 걸리면 안내를 띄우고 기다렸다가 자동으로 이어 간다. 중단·이어하기 가능. 진행률 표시.
- 키가 없으면 생성 버튼 자리에 복사·붙여넣기 모드(5절)를 보여 준다.
- 설정 화면에 고정 안내: "무료 등급은 보낸 내용이 서비스 개선에 쓰일 수 있어요. 앱은 가명만 보내지만 메모에 민감한 내용은 쓰지 마세요."
- AI 호출부는 `provider` 한 파일로 분리(입력: system 텍스트, user 텍스트 → 출력: 응답 텍스트).

## 5. 예비 흐름: 복사·붙여넣기 생성

1. 교사가 학생·항목을 고르고 [프롬프트 복사]를 누른다.
2. 앱이 `buildSystemPrompt(section, opts)` + 기재요령 발췌·참고자료 + `buildUserText(section, opts, student)`를 **한 덩어리의 텍스트**로 합쳐 클립보드에 복사한다. (claude.ai 채팅엔 system 칸이 없으므로 맨 앞에 "아래 지침에 따라 JSON만 출력하라" 성격의 구분 머리말을 붙인다. 머리말은 앱 코드에 두고, `sengibu-prompt.js` 문구는 손대지 않는다.)
3. 교사가 claude.ai 새 채팅에 붙여넣고, 받은 답을 복사한다.
4. 앱의 [답 붙여넣기] 칸에 붙여넣으면, 앱이 JSON을 읽어(코드블록 감싸기 제거 — `generateDraft`의 파싱 방식과 동일) 결과 화면에 띄운다. JSON이 아니면 원문을 초안으로 넣고 경고 "응답이 JSON 형식이 아님 — 직접 확인 필요"를 단다.
5. `student_id`가 지금 학생의 가명과 다르면 경고를 띄우고 저장 전에 확인받는다(다른 학생 답을 잘못 붙여넣는 실수 방지).

**반 전체 진행 모드**: 번호 순서로 한 명씩 넘어가는 화면. [복사] → (claude.ai에서 답 받기) → [붙여넣기] 하면 자동으로 다음 학생으로 넘어가고, 다음 학생의 프롬프트에는 방금까지 받은 초안들의 첫 어절이 `usedOpenings`로 들어간다. 학생을 묶어서 한 번에 보내지 않는다.

**관찰 기록이 하나도 없는 학생**(칩·등급·메모 모두 없음): 복사 대신 `generateDraft`와 같은 기본 결과(`[보충 필요: 관찰 기록 없음]`)를 바로 넣는다.

**같은 채팅 재사용 주의**: 이전 학생 대화가 남은 채팅에 붙이면 다른 학생 내용이 섞일 수 있으므로, 복사 버튼 옆에 "새 채팅에 붙여넣으세요" 안내를 둔다.

## 6. 입력 방식 (항목별)

모든 칩·등급 선택은 날짜(선택한 날)와 함께 저장되고, AI에는 관찰 기록(`logs`)으로 넘어간다. 예: `{ date: "2026-11-17", text: "칩: 발표 잘함" }`. 날짜 있는 메모는 그대로 `logs`로, 날짜 없는 메모는 `memo`로 넘긴다.

### A. 교과 평어
- 설정에서 **평가계획 양식**(앱이 제공하는 엑셀 양식)을 올리거나, 표를 복사해 붙여넣는다(탭 구분 텍스트).
- 양식 열: `교과 | 영역(단원) | 성취기준 코드 | 평가요소 | 매우잘함 | 잘함 | 보통 | 노력요함`. "매우잘함" 칸이 비면 그 행은 3단계로 본다.
- 교과 탭 → 학생마다 평가요소별 등급 버튼. [반 전체 같은 등급] 일괄 버튼.
- AI에 넘기는 것: 학생이 받은 등급의 기준 문장(logs), 해당 교과 성취기준·평가기준 전체(extraDocs), 메모.
- opts: `{ subject, grade }`.

### B. 창체
- 설정에서 **행사 목록**: 영역(자율·자치활동 / 동아리활동 / 진로활동), 행사 이름, 짧은 설명. 이 목록이 extraDocs의 [학교 교육활동 목록]이 된다.
- 학생마다 참여 체크(기본값: 모두 참여), **역할 칩**(예: 사회 맡음, 기록 담당, 자료 준비, 아이디어 제안, 발표, 끝까지 참여), 메모.
- opts: `{ area }`.

### C. 행발
- **칩이 주 입력.** 짧고 교사 말투인 칩(예: 발표 잘함, 집중 잘함, 공부 잘함, 교우 관계 좋음). 성품·학습·친구·생활·표현·노력할 점 묶음, 묶음당 10개 안팎, 중복 없음. 부정 칩도 같은 화면에 둔다.
- 메모는 선택.
- 교사가 설정에서 칩을 더하고 뺄 수 있다.
- 부정 칩만 있고 구체 메모가 없으면 AI가 조심스럽게 쓰거나 warnings에 적을 수 있다 — 프롬프트 규칙 5번에 따른 의도된 동작.
- opts: `{}`.

### D. 통지표 종합의견
- 별도 입력 없음. 행발 칩·메모 + 교과 등급을 재료로 쓴다.
- opts: `{ maxChars, hasSchoolGuide }` — 글자 수와 학교 지침 유무는 설정에서.

### 공통
- **재료가 같은 학생 알림**: 같은 항목에서 칩·등급·메모가 완전히 같은 학생들이 있으면 "3번과 7번의 재료가 같아요. 메모를 한 줄 더하면 달라져요" 알림. 그래도 진행은 가능.
- **길이 선택**: 짧게 / 보통 / 길게 — memo에 "분량: 짧게" 식으로 덧붙인다.
- **반 전체 추가 지시**(선택): 설정에 적으면 모든 학생 memo 뒤에 붙는다.

## 7. 화면

1. **설정**: 학년, 기재요령 발췌 텍스트, 평가계획 양식(내려받기/올리기/붙여넣기), 행사 목록, 칩 목록 편집, 통지표 글자 수·지침, 반 전체 추가 지시, 바이트 상한(항목별, 기본값은 아래 8절).
2. **학생 목록**: 실명 붙여넣기(엑셀·한글에서 여러 줄) → S01, S02… 자동 부여. 대응표는 localStorage에만.
3. **입력**: 항목 탭(교과/창체/행발) → 학생별 칩·등급·메모. 일괄 버튼.
4. **초안 만들기**: 항목·옵션 선택 → 한 명씩 또는 반 전체 진행 모드.
5. **결과 검토**: 초안 편집 박스, `neisBytes()` 실시간 표시(상한 초과 시 빨간색), "[보충 필요" 부분 빨간 강조, 옆에 evidence/warnings/missing. "검토 완료" 체크해야 복사 버튼 활성화. 화면에서만 가명→실명 치환. [검토 완료된 것 번호순 모두 복사].
6. **백업**: 전체 자료를 JSON 파일로 내려받기/불러오기 (브라우저 저장이 지워질 때 대비).

## 8. 열린 사실 확인 (빌더가 구현 전에 확인)

- 항목별 바이트 상한: 참고 도구(ACE)는 행발 1500바이트를 쓴다. 첨부된 「2026학년도 학교생활기록부 기재 길라잡이(초등학교)」에서 교과·창체 영역별·행발 상한을 확인해 설정 기본값으로 넣는다. 설정에서 바꿀 수 있게 한다.
- `neisBytes`의 한글 3바이트·줄바꿈 2바이트 가정도 같은 문서로 확인한다. 다르면 `sengibu-prompt.js`는 고치지 않고 앱 쪽에 보정 함수를 두지 말고 교사에게 먼저 알린다(프롬프트 파일 수정 금지 규칙 때문).

### 검토 후 정한 것 (설계자 판단 — 교사 확인 대상)

- **기재 길라잡이 위치**: `C:\Users\user\Desktop\2026학년도 학교생활기록부 기재 길라잡이(초등학교).pdf`. 확인이 안 되면 행발 1500바이트를 기본값으로, 나머지 상한은 비워 두고 "미확인 — 기재요령에서 확인 후 입력" 표시를 띄운다. `neisBytes`는 원문 그대로 쓴다.
- **메모 속 실명 처리**: 프롬프트를 복사하기 직전에 학생 목록의 실명을 찾아 해당 가명(S번호)으로 자동 치환하고, "실명 2곳을 가명으로 바꿔 복사했어요" 알림을 띄운다. 명단에 없는 이름(가족 등)은 잡을 수 없으므로 메모 칸 아래에 "이름·연락처·건강·가정 정보는 쓰지 마세요" 안내를 고정으로 둔다.

- 프론트엔드 도구: 정적 빌드가 되는 것이면 됨. 제안: Vite + React + Tailwind, 엑셀은 SheetJS로 브라우저에서 읽기, GitHub Actions로 Pages 배포.
- localStorage 저장 구조.
- 복사 머리말의 정확한 문구(프롬프트 파일 바깥, 짧게).

## 10. 요청서와 달라진 점

| 요청서 | 이 설계 | 이유 |
|---|---|---|
| Next.js + Vercel | 정적 사이트 + GitHub Pages | 교사가 GitHub 배포 원함 |
| 서버 `/api/draft`에서 `generateDraft()` 호출 | 브라우저에서 무료 Gemini API 직접 호출 (예비: 복사·붙여넣기) | 비용 0원, 서버 없음 |
| 환경변수 API 키·모델명 | 교사가 설정 화면에 넣은 키·모델명 (localStorage) | 위와 같음 |
| 관찰 기록: 날짜+내용 자유 입력 | 칩·등급 버튼 주 입력 + 메모 보조 | 입력 속도, 교사 선택 |
| 참고자료: 자유 텍스트 붙여넣기 | 평가계획은 정해진 엑셀 양식, 창체는 행사 목록 | 학교마다 다른 양식 분석 부담 제거 |
| — | 재료 같은 학생 알림, 일괄 설정, 길이 선택, 추가 지시, 백업 | 겹침 방지, 참고 도구 장점 반영 |
